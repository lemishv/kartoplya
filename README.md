# Картопля · контур v39

Облік картоплі на складі: сорти → ID → шеди → стопки. Працює офлайн, встановлюється на телефон.

```
index.html             застосунок
manifest.webmanifest   встановлення на головний екран
sw.js                  робота без мережі
icons/                 іконки (SVG, PNG, maskable)
fonts/                 Manrope локально + ліцензія OFL
tests/smoke_test.py    автотест, 102 перевірки
```

## Як викласти

1. Поклади всі файли й папки в корінь репозиторію GitHub Pages, зберігши структуру.
2. Відкрий адресу в Chrome на телефоні → меню ⋮ → «Установити застосунок».
3. Після першого відкриття з мережею далі все працює і без неї.

Якщо кладеш у той самий репозиторій, що й робоча версія, нова версія одразу побачить ті самі дані: база `kartoplya`, схема 3, без міграцій.

## Перший запуск

1. Натисни іконку бази вгорі праворуч → **«Дані»**. Там же тепер і мова інтерфейсу.
2. «Поділитися копією» (або «Зберегти файлом») і надішли файл собі в Drive, пошту чи Telegram.
3. Там само глянь **«Перевірка даних»**. Якщо старі версії лишили дублікати, ящики без шеду чи відʼємні числа, тут видно, що саме і як виправити.

Жовта крапка на іконці бази означає, що після останньої копії були зміни, а сама копія старша за 3 дні.

## Оновлення і відкат

- Новий `index.html` застосунок підхопить у фоні й покаже з наступного відкриття.
- Якщо додаєш або перейменовуєш файли, підніми `VERSION` у `sw.js`.
- Відкат: поверни старий `index.html`. Схема бази та сама, тож дані на місці.

## Тестова копія, що не чіпає справжні дані

У `index.html` зміни один рядок:

```js
const DB_NAME = 'kartoplya-test';
```

Це окрема база на тому ж домені. Імпортуй туди свою копію й експериментуй.

## Автотест

```bash
pip install playwright
python -m playwright install chromium
python tests/smoke_test.py
```

Тест піднімає локальний сервер, проганяє всі сценарії в Chromium і завершується кодом 0, якщо все зелене.

## Що нового у v39

**Виправлено режим обертання стопок.** Тап по стопці спрацьовував із затримкою 230 мс, і якщо наступний тап приходив раніше, попередній скасовувався. П'ять швидких тапів давали одне обертання — останнє. Обертання цілого ряду працювало справно, бо воно йшло іншим шляхом.

- Тепер у режимі обертання тап спрацьовує одразу, без затримки.
- Довге натискання в цьому режимі більше не знищує стопку.
- Швидке малювання висот теж більше не губить тапів: тап по іншій стопці спершу застосовує попередній.
- Обертання ряду прибирає окремі позначки в ньому, щоб вони не лишалися невидимими в даних і не зринали, коли обертання ряду знімеш.
- У режимі обертання показується своя підказка.

**Дві різні ID в одній стопці.** Це працювало й раніше, але побачити мішанину можна було лише тапом. Тепер на схемі така стопка підписана «2 ID», пофарбована кольорами обох сортів і позначена ✦. У заголовку вікна стопки видно заповнення («7 / 7 ящ. · 2 ID»), а самі ID перелічені окремими рядками. Повна стопка на карті завезення тепер має підказку «Стопка заповнена».

## Що нового у v38

**Закриття вікон.** Форми сорту й ID і вміст стопки мають ✕. Системний жест «Назад» на Android тепер закриває відкрите вікно, а не весь застосунок.

**Операції заднім числом.** У кожному вікні операції (завезення, розміщення, продаж, переміщення, сортування, списання) є рядок «Дата». Тап по ньому відкриває вибір дати й часу.

- Обрана дата діє на всі наступні операції, поки не натиснеш ✕. Весь цей час унизу горить жовта плашка «Заднім числом», тож не забудеш її вимкнути.
- Після перезапуску застосунку знову діє «зараз».
- Кожен запис памʼятає, коли його насправді внесено. Журнал показує «внесено …» біля записів заднім числом.
- Застосунок не прийме дату в майбутньому, а також дату, ранішу за ту, коли цей ID потрапив у шед.
- Паспорт рахує дні зберігання від дати операції, а не від дати внесення.

**Білий — колір головного сорту.** Замість першого зеленого. Сорти, які мали цей колір, стали білими. У світлій темі білий показується темним, інакше він зливався б із фоном.

**Бирки ID** — без декоративних скоб.

## Що нового у v37

**Завезення кількістю.** У вікні завезення є перемикач «По стопках / Кількістю». Кількістю — ящики лягають у шед без позиції, розмістити їх можна пізніше. Режим запамʼятовується. Для шеду без намальованої схеми доступне саме завезення кількістю.

**Зняття з «без позиції».** На карті зняття ці ящики мають окрему клітинку: їх можна продати, перемістити, сортувати чи списати, не розміщуючи. На плитці шеду видно, скільки лежить без позиції.

**Паспорт ID.**
- Бирка з кодом у кольорі сорту, сорт, поле, клас і характеристики.
- Звірка: надійшло = на складі + продано + списано + відходи сортування. Якщо не сходиться, це показано разом із розбіжністю.
- Перше й останнє завезення, скільки днів на складі.
- Де лежить: кожен шед з датою «у шеді з», розмірами, «без позиції» і «поза схемою».
- Кожне сортування з результатом і відсотком відходів, продане за розмірами.
- Історія операцій цього ID; тап по рядку відкриває сторно.
- Кнопки «Завезти», «Зняти», «Розмістити».

**Бирки замість однакових плиток.** ID на сторінці сорту виглядає як наліпка з ящика, а сорт лишився плашкою з картоплинкою. Угорі паспорта є ланцюжок «Сорти › Orla».

**Пошук ID.** Лупа вгорі на всіх екранах. «17» знаходить «017», також шукає за полем, класом, сортом і характеристиками. Enter відкриває паспорт, порожній пошук показує нещодавні ID.

**Дрібне**
- Мова інтерфейсу переїхала в «Дані», щоб звільнити місце для пошуку.
- У журналі стопки записуються діапазонами («стопка 1–3, 5»), а завезення кількістю позначене «без позиції».

## Що змінилось у v36 (порівняно з kontur-35)

**Облік**
- Усі рухи ящиків ідуть через один механізм: перевірка → запис однією транзакцією (партії й журнал разом). Якщо в стопці бракує ящиків, операція не пишеться, а повідомлення каже, чого бракує.
- Виправлено обидва баги з червневої перевірки. Перший: дублікати партій після сторно. Другий: тихе списання «з першої локації», через яке програма списувала не ту стопку.
- Меню стопки на схемі тепер відкриває «Зняти зі складу» з уже вибраною стопкою. Старі кнопки «Сортувати / Продати / Перемістити» прибрано: перша падала, дві інші псували дані.
- Сторно перевіряє, чи ящики там, куди їх поклала операція. Якщо ні, відмовляє. Старі записи, які не можна скасувати безпечно, позначені «без сторно».
- Шед: зменшення сітки більше не лишає зайвої місткості, а стопки з ящиками прибрати не можна.
- «Без позиції» показує окрему картку на кожен розмір. Раніше різні розміри зливались в одну картку.
- «Поза схемою»: ящики на позиціях, яких немає в сітці, тепер видно, і їх можна зняти.
- Переміщувати можна і в той самий шед (переставити). Після переміщення одразу відкривається розміщення по стопках.

**Дані**
- Новий екран «Дані»: копія JSON, відновлення з файлу, страховка перед імпортом і стиранням, перевірка й виправлення аномалій зі старих версій.
- «Стерти всі дані» переїхало сюди зі статистики.

**Інтерфейс і PWA**
- Світла тема: нижня панель світла, кільце вибраного кольору видно.
- Тап у поле числа не стирає клітинку.
- Відмінки: «1 сорт, 2 сорти, 5 сортів».
- Помилки показуються червоним і довше.
- Додано маніфест, service worker та іконки.
- Шрифт тепер лежить локально, Google Fonts більше не потрібні.
